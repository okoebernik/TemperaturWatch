1. Introduction

TemperaturWatch is a temperature and humidity gateway based on the Waveshare ESP32-P4-WIFI6-POE-ETH. It reads Dallas DS18B20, DHT11, and AM2301 sensors, switches digital outputs (e.g. relays for fans or alarm devices) manually or automatically via threshold rules, and provides all values through a web interface, REST API, MQTT, and SNMP. This manual is written for administrators who install the device, integrate it into the network and monitoring environment, and operate it.

Notice on use TemperaturWatch is a monitoring and convenience device and not a safety-certified protection system. Wherever a failure could cause injury or significant damage (e.g. over-temperature protection), an independent protection device must be provided. Selecting and protecting the connected loads is the operator's responsibility.

Hardware overview

The board carries an ESP32-P4 (32 MB flash, 32 MB PSRAM). WiFi/Bluetooth is provided by an onboard ESP32-C6 co-processor; Ethernet runs through the internal MAC with an IP101 PHY and works without configuration. Sensors and IOs can only be connected to the 28 GPIOs of the 40-pin header; all other GPIOs are used internally (Ethernet, WiFi link, SD card, USB, display, audio) and are rejected by the firmware. All GPIOs operate at 3.3 V.

2. Commissioning

Flashing the firmware (first installation)

A new board only needs to be flashed once via USB; all further updates run over the network (chapter 11). The five files (bootloader.bin, partition-table.bin, ota_data_initial.bin, temperaturwatch.bin, www.bin) are available on the GitHub release page. Put all files in one folder, connect the board via USB, and run (adjust the port; use python -m esptool instead of esptool if necessary): 

python -m esptool --chip esp32p4 -b 460800 --before default_reset --after hard_reset write_flash \
  --flash_mode dio --flash_size 32MB --flash_freq 40m \
  0x2000 bootloader.bin  0x8000 partition-table.bin  0x10000 ota_data_initial.bin \
  0x20000 temperaturwatch.bin  0x820000 www.bin
Choose the right port If several ESP32 devices are connected to the computer, verify the target's identity before flashing (esptool chip_id or MAC address) so that the wrong device is not overwritten.

Finding the device on the network

  1. Connect the Ethernet cable (the port supports PoE; alternatively power the board by other means). The device obtains its address via DHCP.
  2. The web interface is reachable at http://temperaturwatch.local/ (mDNS hostname, changeable under "Network"). If mDNS does not work on your network, look up the assigned IP address in the DHCP list of your router/server or read it from the serial log (115200 baud).
  3. The web UI is reachable without a password from the factory – see chapter 12.

First steps

1
Open the web interface and choose the language at the top right (English is the default).
2
Under Network, enter WiFi credentials and a hostname if needed, and optionally assign a static IP (2.4 GHz networks only).
3
Create the sensors under Sensors, and outputs/inputs and rules under IOs.
4
Set up the connection to your broker or monitoring system under MQTT and SNMP.
5
Under System, check the time/timezone and enable a login.

4. Dashboard

The dashboard shows all sensors (type, GPIO, label, reading, age of the reading, status) and all IOs and refreshes every four seconds. Outputs without a rule can be switched on and off directly with a button; for outputs with an active threshold rule, the rule ("Automatic: …") is shown instead and manual switching is blocked.

5. Sensors

TypeNotes

Creating a sensor

1
Choose + Sensor, set the type, and enter a label (max. 47 characters). The technical ID used in MQTT topics and the REST API is derived from the label.
2
Click the GPIO of the header. Struck-through GPIOs are already in use.
3
Dallas only: use Scan bus to load the ROM IDs found on the GPIO and pick the desired sensor. Without a selection, the first device found is always read – this only makes sense with one sensor on the bus.
4
Set the poll interval in seconds (default 10 s, minimum 2 s) and save.
Wiring Power sensors with 3.3 V. The data line usually needs a pull-up (typically 4.7 kΩ to 3V3); many sensor modules already include one. For long cables, make sure the ground connection is clean.

6. Digital IOs

SettingMeaning
TypeDigital output or Digital input (inputs use an internal pull-up, without debouncing)
Inverted (active-low)Reverses the logic; "ON" then corresponds to a low level on the pin
Initial state: ONState of an output right after boot
Threshold ruleSwitches an output automatically based on a sensor value (see below)
Switching loads The GPIOs are not designed to drive relay coils or other loads directly. Always drive outputs through a relay module or a driver stage.

Threshold rule with hysteresis

A rule links a sensor and its measured value (temperature or humidity) with a condition (>, ≥, <, ≤) and a threshold. The hysteresis prevents rapid on/off switching (relay chatter) near the threshold:

Example: fan relay Condition "> greater than", threshold 25 °C, hysteresis 1 °C: the output switches on as soon as the temperature rises above 25 °C and only switches off again once it reaches or falls below 24 °C. For "<"/"≤" it works the other way round (off only above threshold + hysteresis). A hysteresis of 0 switches exactly at the threshold.

While a rule is active, it controls the output; manual switching (web UI, REST API, MQTT) is rejected. If the sensor delivers no valid reading, the rule leaves the output unchanged. To switch manually, remove the rule.

7. Network

The Status panel shows the connection state with the current IP address per interface, as well as the mDNS hostname. Ethernet and WiFi can be active at the same time and then have separate addresses.

SettingMeaning
SSID / passwordWiFi credentials (2.4 GHz only). An empty password field keeps the existing password. Without an SSID, WiFi stays inactive.
Hostname (mDNS)The device is reachable at http://<hostname>.local/ (max. 31 characters)
Static IPCan be enabled separately per interface: IP address, subnet mask, gateway, optional DNS server. Disabled = DHCP.

Save & restart saves the settings and restarts the device – network changes only take effect after the restart.

Danger: device no longer reachable A wrong combination of IP address, subnet mask, and gateway makes the device unreachable over the network after the restart (web UI, REST API, MQTT, and SNMP all depend on the same interface). Check the values carefully before saving and never assign the same static IP to Ethernet and WiFi on the same network. Recovery is then only possible via a serial connection (reflashing, see chapter 11).

8. MQTT

1
Turn on Enabled and enter the broker URI (mqtt://host:1883 or mqtts://host:8883).
2
If needed, set username/password (empty password = unchanged), the base topic (default temperaturwatch), and the publish interval (default 30 s, minimum 5 s). With several devices on one broker, give each device its own base topic.
3
For mqtts://, paste the broker's CA certificate (PEM). Client certificates (mTLS) are not supported.
4
Save – the connection is re-established immediately, no restart needed. The badge shows the status.

9. SNMP and monitoring

The SNMPv1/v2c agent listens on UDP port 161. Enabling or disabling it requires a restart; changing the community or the system fields (sysName, sysContact, sysLocation) takes effect immediately. The default community is public – change it for production use.

OID (base 1.3.6.1.4.1.99999.1)Content
.2.1.0sensorCount
.2.2.1.{1..8}.<n>sensorTable: index, ID, label, type, temperature×10, humidity×10 (−1 = n/a), valid, age (s)
.3.1.0ioCount
.3.2.1.{1..5}.<n>ioTable: index, ID, label, type, state
.1.1.0 … .1.5.0System fields (private); additionally the standard MIB-II group 1.3.6.1.2.1.1.*
Table index is not stable The row numbers of the sensor and IO tables result from the order of the configuration. If an entry is deleted from the middle, the following ones move up. Monitoring sensors that query a fixed OID including the row number (e.g. PRTG "SNMP Custom Table") may then show the values of a different sensor. After deleting an entry, check or recreate the monitoring sensors.

Monitoring integration: A step-by-step guide for PRTG (no plugin, using "SNMP Custom Table") is on the Help page and in docs/PRTG_SETUP.en.md; for CheckMK there is a ready-made plugin in contrib/checkmk/. Device discovery works because, besides the private MIB, the device also answers the standard MIB-II system group (including sysObjectID).

10. System

Information and restart

The cards show firmware version and build date, chip, uptime, and free heap. Restart reboots the device; the configuration is kept. Factory reset deletes the network, MQTT, SNMP, sensor, IO, and login configuration and restarts; the time settings are kept. Afterwards the device is reachable without a password again.

Time (NTP)

NTP is active from the factory (server pool.ntp.org, timezone Europe/Berlin). The badge shows synced or waiting for sync. Choose the timezone from a list of common regions, or any other one via "Custom" as a POSIX TZ string (e.g. CET-1CEST,M3.5.0,M10.5.0/3). On networks without internet access, enter an internal NTP server; the device needs access to UDP port 123. Changes take effect immediately.

Login

Enables password protection (HTTP Basic Auth) for the web interface and the REST API. A password must be set before login can be enabled. Changes take effect immediately; afterwards the browser asks for the credentials.

11. Updates (OTA)

Firmware and web UI are updated independently over the network – in the web UI under System → Firmware update or via curl. No USB cable is needed.

FilePurposeBehavior
temperaturwatch.binApp firmwareWritten to the inactive OTA slot; the device then restarts automatically
www.binWeb UI and helpWritten directly to the web partition; no restart, the web UI is briefly unavailable meanwhile
curl -X POST --data-binary @temperaturwatch.bin http://<ip>/api/system/ota
curl -X POST --data-binary @www.bin             http://<ip>/api/system/ota-web
1
Update the firmware first and the web UI after the restart; always use both from the same release.
2
Reload the browser page (Ctrl+F5) so the new interface is loaded.
Automatic rollback If the new firmware does not start cleanly (crash or hang before reaching the main loop), the bootloader automatically returns to the previous version on the next start.
Recovery via USB If the web UI is no longer reachable after a failed web UI update, or the device can no longer be reached on the network, the only remedy is reflashing via USB using the command from chapter 2. For a complete fresh start without the old configuration, first run esptool --chip esp32p4 erase_flash.

12. Security and operation

  • Enable the login (System → Login). No password is set from the factory so that you are not locked out after a factory reset.
  • The web interface and REST API run over unencrypted HTTP; Basic Auth transmits credentials unencrypted. Operate the device only on trusted networks or isolate it with a VLAN/firewall.
  • Change the SNMP community; SNMPv1/v2c transmits it in clear text and offers no encryption (no SNMPv3).
  • Use MQTT with TLS (mqtts://) and authentication if the broker is outside the local network. The broker must restrict write access to …/io/+/set with an ACL – anyone who may publish there can switch outputs.
  • Passwords are never returned by the REST API or web UI; an empty password field when saving keeps the existing one. The login password is stored only as a hash; WiFi and MQTT passwords are kept in the device's configuration storage.

Backing up the configuration

There is no export button, but the configurations can be read via the REST API and (for sensors and IOs) restored with PUT. Passwords are not included and must be re-entered when restoring. 

for p in sensors/config io/config network/config mqtt/config snmp/config time/config; do
  curl -s http://<ip>/api/$p -o "backup_$(echo $p | tr / _).json"
done

13. Troubleshooting

SymptomCause / remedy
Web UI not reachableCheck link LED/cable; look up the IP in the DHCP list or try temperaturwatch.local; after a wrong static IP, only reflashing via USB helps
WiFi does not connectCheck SSID/password; 2.4 GHz networks only; was the device restarted after saving? Without an SSID, WiFi stays inactive
Sensor shows "Error" or "waiting"Check wiring and 3.3 V supply, pull-up on the data line, correct GPIO, poll interval at least 2 s; Dallas: use "Scan bus" to check whether the sensor is found and the ROM ID matches
Dallas bus scan finds nothingPull-up (4.7 kΩ to 3V3) missing, data/ground swapped, or wrong GPIO
Output cannot be switchedA threshold rule is active (manual switching blocked) – remove the rule; with inverted logic, "ON" corresponds to a low level
MQTT stays "disconnected"Check broker URI (mqtt:///mqtts://), credentials, firewall; for TLS, store the matching CA certificate
SNMP does not respond / "restart needed"Restart the device after enabling; check community and UDP port 161. Monitoring tools need the standard MIB-II system group for discovery – it is present

Wrong time (daylight saving)Check the timezone (choose a POSIX TZ string with a daylight saving rule)
Forgot the passwordA reset via the interface is not possible (the factory reset is protected as well). Erase with erase_flash via USB and reflash – the entire configuration is lost
Old version runs after an updateThe new firmware did not report itself as valid and was rolled back automatically – repeat the update, or flash via USB if necessary
